## Step-by-Step Console Walkthrough

### Step 1: Create the Custom IAM Policy
1. Log in to the [AWS Management Console](https://console.aws.amazon.com/) as an **Administrator / Root user**.
2. In the top search bar, type **IAM** and press Enter.
3. In the left navigation menu, click **Policies**, then click the orange **Create policy** button.
4. On the top right of the policy editor, switch to the **JSON** tab.
5. Delete the default placeholder text and paste the entire JSON from [`iam-network-admin-policy.json`](file:///g:/My%20Drive/AWS/iam-network-admin-policy.json).
6. Click **Next** at the bottom right.
7. Under **Policy name**, enter:
   ```text
   NetworkAdministratorFullAccess
   ```
8. *(Optional)* Add a description: `Comprehensive network administration permissions including VPC, TGW, Route53, ELB, DirectConnect, Network Firewall, and Flow Logs.`
9. Click **Create policy**.

---

### Step 2: Create the Network Admins Group
Using groups allows you to easily add or remove network administrators without managing individual permissions.

1. In the left navigation menu under IAM, click **User groups**.
2. Click the orange **Create user group** button.
3. Under **User group name**, enter:
   ```text
   NetworkAdmins
   ```
4. In the **Attach permissions policies** search bar:
   - Search for `NetworkAdministratorFullAccess` (the policy you created in Step 1) and check its box.
   - *(Optional Best Practice)* Search for `IAMUserChangePassword` and check its box so the user can change their own initial password.
5. Click **Create user group** at the bottom.

---

### Step 3: Create the Network Administrator IAM User
1. In the left navigation menu under IAM, click **Users**.
2. Click **Create user**.
3. Under **User details**:
   - **User name**: `network-admin` (or any username you choose, e.g. `john-netadmin`).
   - Check the box: **Provide user access to the AWS Management Console**.
4. Under **Are you providing console access to a person?**:
   - Select **I want to create an IAM user**.
5. Under **Console password**:
   - Select **Custom password** and type a secure password (or choose *Autogenerated password*).
   - *(Recommended)* Keep **Users must create a new password at next sign-in** checked.
6. Click **Next**.
7. Under **Set permissions**:
   - Select **Add user to group**.
   - Check the box next to the **NetworkAdmins** group created in Step 2.
8. Click **Next**.
9. Review the settings and click **Create user**.
10. **Save the Credentials**:
    - Copy or download the **Console sign-in URL**, **User name**, and **Password**.

---

### Step 4: (Crucial Best Practice) Enable MFA (Multi-Factor Authentication)
1. Sign in to the AWS Console using the new **Console sign-in URL** and the credentials created in Step 3.
2. In the top-right corner, click on your username/account name and select **Security credentials**.
3. Under **Multi-factor authentication (MFA)**, click **Assign MFA device**.
4. Enter a device name (e.g. `AdminPhoneAuth`) and select **Authenticator app** (Google Authenticator, Microsoft Authenticator, Authy, etc.).
5. Scan the QR code with your mobile authenticator app, enter two consecutive 6-digit codes, and click **Add MFA**.

## Testing & Verifying Permissions

1. **Test Allowed Actions**:
   - Go to **VPC Console** -> Create a new VPC, Subnet, Route Table, and Security Group. Everything will work smoothly.
   - Go to **Route 53** -> Create Private Hosted Zone.
2. **Test Denied / Restricted Actions**:
   - Go to **EC2 Console** -> Try to launch an EC2 instance (`t3.micro`). AWS will block it because compute provisioning is restricted to compute/system admins.
   - Go to **RDS Console** -> Try to create a database instance. AWS will block it with an Access Denied error.
